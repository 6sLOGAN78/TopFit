<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client headers/query -> logs | Authorization, Cookie, X-Request-ID and query strings are attacker/user controlled |
| app code -> stdout logs | Future resume text and chat messages could be logged by mistake |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-30 | Information disclosure | ranker/observability.py | mitigate | redact processor last before JSONRenderer in the shared ProcessorFormatter, covering structlog, stdlib extras and exception text; tests on rendered output |
| T-01-31 | Information disclosure | exception tracebacks | mitigate | ExceptionDictTransformer(show_locals=False); test with a secret local |
| T-01-32 | Information disclosure | access logs / query strings | mitigate | RequestLogMiddleware logs path only; uvicorn access log disabled (image CMD --no-access-log in plan 01-04, logger level WARNING here) |
| T-01-33 | Tampering | log injection via X-Request-ID | mitigate | asgi-correlation-id UUID4 validator regenerates invalid IDs; test sends a newline payload |
| T-01-34 | Repudiation | request traceability | mitigate | request_id on every request log line and echoed in the X-Request-ID response header |
| T-01-35 | Information disclosure | third-party loguru output (fastembed) bypassing redaction | mitigate | loguru default sink removed and forwarded into stdlib logging, so it passes through the same formatter |
</threat_model>

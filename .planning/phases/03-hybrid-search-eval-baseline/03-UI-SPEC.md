## Spacing Scale

Declared values (multiples of 4; Tailwind 4 default `--spacing: 0.25rem`):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-text gap inside badges, chips and buttons |
| sm | 8px | `2` | Gaps between badges, between chips, between rows inside a card |
| md | 16px | `4` | Card padding, gap between cards, page gutter on mobile, gap between search input and button |
| lg | 24px | `6` | Page gutter at ≥ 640px; gap between the chip area and the results list |
| xl | 32px | `8` | Gap between hero blocks (heading group → search form → examples → count) |
| 2xl | 48px | `12` | Hero top padding on mobile; gap above the footer |
| 3xl | 64px | `16` | Hero top padding at ≥ 640px |

Exceptions:
- **44px (`h-11`)**: search input and Search button height, the settings icon button (`size-11`), and the "Load more" button. These are touch targets for the main actions (WCAG 2.5.5 advisory size).
- **56px (`h-14`)**: site header height. The 44px settings button is vertically centred in it (`items-center`); do not add vertical padding.
- **20px (`h-5`)**: badges have a fixed outer height of 20px with their content centred (`items-center`). Size and position badges by that outer height, never by inner padding.
- Chips are `h-8` (32px) with an 8px gap, which meets WCAG 2.2 SC 2.5.8 (24px minimum target plus spacing).

## Typography

Exactly 4 sizes and 2 weights. **[default]**

| Role | Size | Tailwind | Weight | Line height | Used for |
|------|------|----------|--------|-------------|----------|

Add to `globals.css`: `--brand`, `--brand-foreground`, `--warning`, `--warning-surface`, `--warning-border` in `:root` and `.dark`, and `--color-brand`, `--color-brand-foreground`, `--color-warning`, `--color-warning-surface`, `--color-warning-border` in `@theme inline`. **Do not repurpose shadcn's `--accent` or `--primary`.** In this preset `--accent` is the grey hover surface for menus, and `--primary` (near-black) stays the default Button colour.

Accent (`brand`) is reserved for exactly these elements:
1. The **Search jobs** submit button (hero and results bar): `bg-brand text-brand-foreground hover:bg-brand/90`.
2. **Query-matched skill badges** on job cards: `bg-brand/10 text-brand` plus a lucide `Check` icon (colour is not the only cue, WCAG 1.4.1). At most **3** brand-styled skill badges per card. Any further query-matched skills use the neutral `secondary` style but keep the `Check` icon and hidden text.
3. The **active-job count number** in the hero (`text-brand font-semibold tabular-nums`).
4. The **selected radio indicator** in the settings sheet.

Everything else uses neutral tokens: chips (`bg-muted`), "Load more" and relax buttons (`outline`), example queries (`outline`), links (`text-foreground underline`). The focus ring stays the preset `ring` (`outline-ring/50`, 3px), not brand.

Contrast floor: all text ≥ 4.5:1, and icons/borders that carry meaning ≥ 3:1 (WCAG 2.1 AA).

## Layout

**[default]** Single centred column at every width. There is no side rail; filters live in a chip row above the results.

### Page frame
- `SiteHeader`: `h-14`, `border-b`, inner container `mx-auto max-w-3xl px-4 sm:px-6`, flex row. Wordmark "TopFit" (16/600) on the left, a link to `/` that clears all params. The settings button (`variant="ghost" size-11`, lucide `Settings2`, `aria-label="Search settings"`) is on the right.
- Main container: `mx-auto w-full max-w-3xl px-4 sm:px-6` (768px max content width).
- Footer: `mt-12 border-t py-6`, 12px muted text: `Job data from public job-board APIs. Each listing links to its original source.`

### Hero state (URL has no `q`) — D-01
Vertical stack, `pt-12 sm:pt-16`, `gap-8`, left-aligned on mobile and centred (`text-center`, form `max-w-2xl mx-auto`) at ≥ 640px:
1. `h1` (Display) + sub-line (16/400, muted) "how it works".
2. Search form: `Input` (`h-11 text-base`, flex-1) + Search button (`h-11`, brand). Below 640px the button stacks under the input at full width.
3. "Try:" label (14/600) + 4 example-query buttons (`variant="outline"`, wrap, `gap-2`). Clicking one fills the input and submits.
4. Active-job count line (14/400, number in brand). While `/api/meta` loads, show a `Skeleton` `h-5 w-56`. If `/api/meta` fails, hide the line (never show 0).

### Results state (URL has `q`)
Stack with `pt-6`:
1. `SearchBar` (same input + brand button, pre-filled). `gap-4` below.
2. `ParseSummary` (12px muted) + `FilterChips` row (`flex flex-wrap gap-2`). Chips wrap on mobile. No horizontal scroll.
3. `SetAsideLine` (14px muted), only when any count > 0.
4. `DegradedNotice` (Alert), only when `degraded`.
5. `h2` "Top matches" (16/600) with a visually-hidden live region beside it. `mt-6`.
6. `ResultsList`: `flex flex-col gap-4`, 20 `JobCard`s.
7. `RelaxSuggestions` when there are 1–4 results (after the list) or 0 results (inside the empty state).
8. "Load more" (`variant="outline"`, `h-11`, full width on mobile, `w-auto mx-auto` at ≥ 640px), or the end-of-list line.

Focal point: the first `JobCard` title is the primary focal point of the results state. The chip row is secondary. The set-aside line and the card footers are tertiary, carried by muted 12–14px text.

Responsive floor: 360px width with no horizontal scrolling. Long company/title strings wrap or truncate as specified under Typography.

## Job Card Contract (D-02, D-03, UI-04)

`Card` with default padding (16px), `gap-2` between rows. It is an `<article>` labelled by its title (`aria-labelledby`). Row order:

| # | Row | Content and format |
|---|-----|--------------------|
| 1 | Title | `h3`, 16/600, `line-clamp-2`. Plain text (not a link) |
| 2 | Company · place | 14/400: `{company} · {place}`. `place` = city (or "Multiple cities: Bengaluru, Pune" up to 2 then "+N"), or "Remote" for remote jobs with no city |
| 3 | Badges | `flex flex-wrap gap-2`, in this order: **work-mode/region badge**, **salary badge**, **stale badge** (if any) |
| 4 | Matched skills | Up to 6 skills, `Badge variant="secondary"`. Query-matched skills come first, with a `Check` icon and visually-hidden text "matches your search". The first 3 of them use brand style (cap of 3 per card). If there are no skills, omit the row |
| 5 | Why it matched | 14/400 muted, from the API's rule-based reason string, e.g. `Matches python, backend · Bengaluru · posted 2d ago`. Prefixed by visually-hidden "Why it matched:" |
| 6 | Footer | `flex items-center justify-between gap-2 pt-2 border-t`. Left (12px muted): `via {Source} · posted {Xd} ago · checked {Yh} ago`. Right: `Button variant="outline"` rendered as `<a href={url} target="_blank" rel="noopener noreferrer">`, label **View posting**, lucide `ExternalLink` icon, visually-hidden "(opens in a new tab)" |

### Work-mode / region badge mapping
| Data | Badge text | Style |
|------|-----------|-------|
| `remote` + `worldwide` / `india` / `apac` | `Remote · India OK` | `secondary`, icon `Globe` |
| `remote` + `unknown` | `Remote · Region not stated` | `outline`, icon `CircleHelp` |
| `remote` + `us_only` | `Remote · US only` | `outline` (shown only when the user's filters let it through) |
| `remote` + `eu_only` | `Remote · EU only` | `outline` |
| `remote` + `other_region` | `Remote · Other region` | `outline` |
| `hybrid` with `onsite_days_per_week` | `Hybrid · {n} days on-site` | `secondary`, icon `Building2` |
| `hybrid` without days | `Hybrid` | `secondary`, icon `Building2` |
| `onsite` | `On-site` | `secondary`, icon `Building2` |
| `unknown` | no badge | — |

### Salary badge
- Range: `₹12–18 LPA`. Single value: `₹15 LPA`. Up to 1 decimal place, trailing `.0` dropped (`₹4.5 LPA`). En dash between values. `tabular-nums`. Icon `IndianRupee` is not used (the ₹ sign is already in the text).
- Estimate (`salary_is_estimate`): `~ ₹12–18 LPA estimate`, `outline` style, with `Tooltip` text `Estimated by Adzuna. The employer did not state a salary.` The tooltip trigger is the badge itself, made focusable (`tabIndex=0`).
- Unknown: `Salary not stated`, `outline`, muted text.

### Stale badge (D-03)
- Text `May be stale` with icon `TriangleAlert`, warning colours (`bg-warning-surface text-warning border-warning-border`).
- It is a `button` that opens a `Popover` listing the reasons (works on touch and keyboard; tooltips alone do not):
  - `stale_60d` → `First seen over 60 days ago and still listed.`
  - `reposted_3x` → `Reposted 3 or more times.`
  - `no_apply_url` → `No direct link to apply.`
  - Popover footer line (12px muted): `We show it anyway, ranked lower. Check the original posting before applying.`
- The badge's accessible name includes the reasons: `May be stale: reposted 3 or more times`.

### Freshness formatting (UI-04)
- `posted`: uses `posted_at`, falling back to `first_seen_at`. Under 24h → `posted today`. 1–59 days → `posted {n}d ago`. 60+ days → `posted {n}mo ago` (n = floor(days/30)).
- `checked`: uses `last_seen_at`. Under 60 min → `checked {m}m ago` (0 → `checked just now`). Under 48h → `checked {h}h ago`. Otherwise `checked {d}d ago`.
- Times are computed client-side from ISO timestamps. Wrap them in `<time dateTime>` with the absolute date in `title`.

### Source attribution
`via {source_display_name}` as returned by the API (e.g. `via Remotive`, `via Adzuna`, `via Greenhouse`). It is always shown and never truncated away.

## Filter Chips Contract (UI-05, D-05, D-09)

- One chip per hard filter present in `parsed.chips` / effective filters: **City**, **Min salary**, **Work mode**, **Seniority**. Skills and role words never become chips (D-05).
- Chip anatomy: a `bg-muted h-8 rounded-4xl` pill made of two buttons.
  - The **label button** (14/400, the value in 600, e.g. `City: **Bengaluru**`) opens the editor `Popover`.
  - The **remove button** (`X` icon, 16px glyph inside a 24px hit area) has `aria-label="Remove filter: City Bengaluru"`.
- **Add filter** button (`variant="ghost"`, `Plus` icon, label `Add filter`) opens a Popover menu of the filter types not set yet. It is hidden when all four are set.
- Chip labels:
  - City: `City: Bengaluru`. Multiple cities: `City: Bengaluru, Pune`. With remote_ok: `City: Bengaluru + remote`.
  - Min salary: `₹10 LPA+`. With estimates excluded: `₹10 LPA+ · no estimates`.
  - Work mode: `Remote`, `Remote or hybrid`, `On-site`, …
  - Seniority: `Senior`, `Junior or mid`, …
- Editors (inside the Popover, `w-72`, `gap-4`). The footer has one button, `Apply filter` (default Button). There is no cancel button. Esc or a click outside closes the popover without applying anything (Base UI Popover default), and focus returns to the chip:
  - **City**: `Combobox` (multi-select) over the city list, plus `Switch` "Also include remote jobs open to India". The city list should come from `GET /api/meta` (add a `cities: string[]` field, sourced from `cities.yaml`). Planner: add this to the API contract.
  - **Min salary**: `Select` with options `Any, ₹3, 4, 5, 6, 8, 10, 12, 15, 18, 20, 25, 30, 40, 50 LPA+` (the same buckets as the parse schema), plus `Switch` "Exclude estimated salaries" (D-09).
  - **Work mode**: `ToggleGroup` (multiple): `Remote`, `Hybrid`, `On-site`.
  - **Seniority**: `ToggleGroup` (multiple): `Intern`, `Junior`, `Mid`, `Senior`, `Lead`.
- **Any chip edit, add or removal** writes the explicit filters to the URL with `auto=0` (`auto_filters=false`), so a removed chip never comes back (Pitfall 8). Then it re-runs the search.
- Model-sourced chips (`source: haiku | jev`) show a small `Sparkles` icon before the label and the visually-hidden text "suggested by {model}". Rule and user chips have no icon.
- `ParseSummary` (12px muted, above the chips): `Read by rules`, `Read by rules + Claude Haiku`, or `Read by rules + Jev`, from `parsed.parse_source`. When the search used no hard filters: `No filters found in your search. Add one below.`

### URL state (D-01)
Shareable, bookmarkable, and restored by back/forward. Param names must mirror the API query params in the generated client. Suggested: `q`, `city` (repeatable), `remote_ok`, `min_lpa`, `no_est`, `mode` (repeatable), `seniority` (repeatable), `auto`. The parse-model preference is **not** in the URL (it is a per-browser setting, see Settings). The page reads `useSearchParams` inside `<Suspense>` (Pitfall 11).

## Set-Aside and Relax Contract (UI-06, D-08, D-10)

- `SetAsideLine` (14px muted, one paragraph, items joined with ` · `), shown when any count > 0:
  `Of the 200 most relevant jobs, set aside: 34 below ₹10 LPA · 12 outside Bengaluru · 8 not senior · 18 US/EU-only remote`
  - Wording per filter: salary `{n} below ₹{x} LPA`; city `{n} outside {city list}`; work mode `{n} not {mode list}`; seniority `{n} not {seniority list}`; estimates `{n} with estimated salary`; geography (D-08, always present when > 0) `{n} US/EU-only remote`.
  - The "200" comes from the API's set-aside universe size (do not hard-code it if the API returns it).
- `RelaxSuggestions`: shown when there are **0 results** (inside the empty state) or **1–4 results** (below the list, under the heading `Too few matches? Try:` 14/600).
  - One `Button variant="outline"` per filter with `relax[f] > 0`, sorted by count descending, max 4:
    - `Remove ₹10 LPA minimum (+34 jobs)`
    - `Include any city (+12 jobs)`
    - `Any seniority (+8 jobs)`
    - `Any work mode (+5 jobs)`
    - `Include estimated salaries (+6 jobs)`
  - Use `job` for a count of 1.
  - Clicking one applies that single relaxation (URL update, `auto=0`) and re-runs the search. Nothing is relaxed automatically (D-10).

## Settings Contract (D-06)

- Trigger: the header settings button. Opens a `Sheet` on the right, `w-full sm:max-w-sm`, with title `Search settings`.
- Field label: `Query parsing model`.
  - If `/api/meta.parse_models` contains more than one model: `RadioGroup`:
    - `Claude Haiku` (default) — description: `Reads the parts of your search that rules can't place, such as unusual city names.`
    - `Jev` — description: `TypeSafe AI's decision model. Experimental.`
  - If it contains only `haiku`: static text `Claude Haiku` (no radio group). Never show a disabled Jev option.
- Help text (12px muted): `Rules always read your search first. The model only sees the words the rules couldn't place, and never your other details. Saved in this browser.`
- The choice is stored in `localStorage` key `topfit.parseModel` and sent as `parse_model` on every search. If the stored value isn't in `parse_models`, fall back to `haiku` silently.
- Changing it while a search is shown re-runs the current search. The sheet stays open, and the change is announced through the results live region.

## States and Interaction Contract

| State | Trigger | UI |
|-------|---------|----|
| Hero idle | No `q` in URL | Hero layout. Input autofocused only on desktop (`(pointer: fine)`), never on mobile |
| Submit empty | Search with blank or whitespace input | No request. `Field` error under the input: `Type a role, skill or city to search.` Focus stays in the input |
| First load | New `q` or filter change | Chips area keeps the previous chips (or nothing on first load). List shows 3 `Skeleton` cards (`h-44`). `aria-busy="true"` on the list. Live region: `Searching…` |
| Results | 200 OK, ≥ 1 item | Cards. Live region: `{n} jobs found` (n = items loaded so far; there is no total) |
| Load more | `next_cursor` present | Outline `h-11` button `Load more jobs`. While fetching: disabled, `Spinner` + `Loading more jobs…`. On success, 20 more cards append, focus stays on the button, and the live region says `20 more jobs loaded` |
| End of list | `next_cursor` null and ≥ 5 items | 14px muted centred line: `That's every match for this search.` |
| Few results | 1–4 items | Cards + RelaxSuggestions block |
| Empty | 0 items, relax suggestions available | `Empty` component (see Copywriting) + relax buttons |
| Empty, nothing to relax | 0 items, no relax counts > 0 | `Empty` with the "no matches anywhere" copy + 4 example-query buttons |
| Degraded | `degraded: true` | `Alert` (default variant, `Info` icon) above the results. Results render normally |
| Rate limited | HTTP 429 (`error.code = rate_limited`) | `Alert` in warning colours with the 429 copy. The previous results (if any) stay visible below it. The Search button stays enabled |
| Error | Network failure, 5xx, or Zod response-validation failure | `Alert variant="destructive"` with the error copy and a `Retry search` Button (outline) that refetches. Previous results stay visible if present |
| Meta failed | `/api/meta` error | Hide the job-count line. The settings sheet shows Claude Haiku only |

Focus and keyboard:
- Enter submits the form. Esc closes popovers and the sheet; focus returns to the trigger (Base UI default).
- After a chip is removed, focus moves to the next chip, or to `Add filter` if none are left.
- After a relax button is clicked, focus moves to the `Top matches` heading (`tabIndex=-1`).
- Everything works with the keyboard alone, and focus is always visible (preset 3px ring).
- One `aria-live="polite"` region is used for all result announcements.
- Respect `prefers-reduced-motion`: no skeleton pulse or popover animation when it is set (`motion-safe:` prefixes).

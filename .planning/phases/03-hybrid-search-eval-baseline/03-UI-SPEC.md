## Spacing Scale

Declared values (multiples of 4; Tailwind 4 default `--spacing: 0.25rem`):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-text gap inside badges, chips and buttons |
| sm | 8px | `2` | Gaps between badges, between chips, between rows inside a card, gap between the hero input and button |
| md | 16px | `4` | Gap between cards, page gutter on mobile, button horizontal padding |
| lg | 24px | `6` | Card padding at ≥ 640px (DESIGN.md `card-base`), page gutter at ≥ 640px, gap between the chip area and the results list |
| xl | 32px | `8` | Gap between hero blocks (heading group → search form → examples → count) |
| 2xl | 48px | `12` | Hero band vertical padding on mobile; gap above the footer |
| 3xl | 64px | `16` | Hero band vertical padding at ≥ 640px |

Only the scale above is used for spacing. DESIGN.md's 12px and 20px spacing values are **not** used, and its 120px hero padding is **not** used either; the band uses 48/64px.

Exceptions:
- **44px (`h-11`)**: search input and Search button height (DESIGN.md `text-input` is also 44px), the settings icon button (`size-11`), and the "Load more" button. These are touch targets for the main actions (WCAG 2.5.5 advisory size).
- **40px (`h-10`)**: standard (non-primary) button height. This is an element height, not a spacing value.
- **56px (`h-14`)**: site header height. The 44px settings button is vertically centred in it (`items-center`); don't add vertical padding.
- **20px (`h-5`)**: badges have a fixed outer height of 20px with their content centred (`items-center`). Size and position badges by that outer height, never by inner padding. DESIGN.md's `2px 8px` tag padding becomes `h-5 px-2`.
- Chips are `h-8` (32px) with an 8px gap, which meets WCAG 2.2 SC 2.5.8 (24px minimum target plus spacing).

## Typography

Exactly 4 sizes and 2 weights, Inter throughout. DESIGN.md roles are folded onto this scale: `caption`/`micro` (12–13px) → Label, `body-sm`/`button-md` → Body, `body-md`/`heading-5` → Heading, `heading-2` → Display. **[default]**

| Role | Size | Tailwind | Weight | Line height | Used for |
|------|------|----------|--------|-------------|----------|
| Label | 12px | `text-xs` | 400 / 600 | 1.4 (`leading-[1.4]`) | Badges (600, DESIGN.md `caption-bold`), card footer (source + freshness), chip "+N" counts, help text |
| Body | 14px | `text-sm` | 400 | 1.5 (`leading-normal`) | Card company/location line, "why it matched" line, chips, set-aside line, alerts, buttons (600), settings descriptions |
| Heading | 16px | `text-base` | 600 | 1.5 (`leading-normal`) | Card job title (`h3`), results heading "Top matches" (`h2`), sheet title, wordmark. Also at 400 with 1.55 line height (`leading-[1.55]`, DESIGN.md `body-md`): the search input text (16px stops iOS zoom on focus) and the hero sub-line |
| Display | 36px | `text-[36px]` | 600 | 1.2 (`leading-[1.2]`) with `tracking-[-0.5px]` | Hero `h1` only, at every width (two lines at 360px is expected) |

Weights: **400 (regular)** and **600 (semibold)** only. Numbers in salary and counts use `tabular-nums`. Job titles clamp to 2 lines (`line-clamp-2`); company names truncate to 1 line with the full name in `title`.

Accent (`brand`) is reserved for exactly these elements. In the spirit of DESIGN.md, there is **at most one solid-purple CTA per view**:
1. The **Search jobs** button in the results-view `SearchBar` (`button-primary`). In the hero band the same action uses `button-on-dark` instead (see below), so the landing view has no solid purple.
2. The **text-input focus border**: 2px `--brand` (DESIGN.md `text-input-focused`). It sits between the white input interior and its surroundings, at 6.57:1 against the white interior.
3. **Query-matched skill tags** on job cards: `badge-tag-purple` (`bg-brand-tint text-brand-tint-foreground`, 11.06:1) plus a lucide `Check` icon (colour is not the only cue, WCAG 1.4.1). At most **3** lavender skill tags per card. Any further query-matched skills use the neutral tag style but keep the `Check` icon and hidden text.
4. The **selected radio indicator** in the settings sheet.

**Hero Search button decision:** the button inside the navy band is `button-on-dark` (white background, ink text), **not** purple. Purple `#5645d4` on navy is 2.75:1, below the 3:1 non-text contrast its boundary needs. A white button is 18.06:1 against navy with no extra outline, matches DESIGN.md's own on-dark component, and keeps the "one purple CTA" rule. The white input and the white button are separated by an 8px gap, and the button's ink label sets it apart from the input.

Everything else is neutral: active filter chips (ink pills), outline buttons, neutral tags, ink text. The hero job-count number is `text-on-dark font-semibold` (purple on navy would fail).

Contrast floor: all text ≥ 4.5:1, and icons, focus indicators and control boundaries that carry meaning ≥ 3:1 (WCAG 2.1 AA).

## Layout

**[default]** Single centred column at every width. There is no side rail; filters live in a chip row above the results.

## Job Card Contract (D-02, D-03, UI-04)

The card is DESIGN.md `card-base`: canvas background, 1px hairline border (`ring-1 ring-border`, replacing base-nova's `ring-foreground/10`), 12px radius (`rounded-xl`) and no shadow. Padding is 16px below 640px and 24px at ≥ 640px (`p-4 sm:p-6`); the 16px keeps 360px layouts usable. Rows have `gap-2` between them. The card is an `<article>` labelled by its title (`aria-labelledby`). Row order:

| # | Row | Content and format |
|---|-----|--------------------|
| 1 | Title | `h3`, 16/600 ink, `line-clamp-2`. Plain text (not a link) |
| 2 | Company · place | 14/400 charcoal (`#37352f`, 12.26:1): `{company} · {place}`. `place` = city (or "Multiple cities: Bengaluru, Pune" up to 2 then "+N"), or "Remote" for remote jobs with no city |
| 3 | Badges | `flex flex-wrap gap-2`, in this order: **work-mode/region tag**, **salary tag**, **stale tag** (if any) |
| 4 | Matched skills | Up to 6 skill tags. Query-matched skills come first, with a `Check` icon and visually-hidden text "matches your search". The first 3 of them use `badge-tag-purple` (cap of 3 per card); the rest use the neutral tag. If there are no skills, omit the row |
| 5 | Why it matched | 14/400 slate, from the API's rule-based reason string, e.g. `Matches python, backend · Bengaluru · posted 2d ago`. Prefixed by visually-hidden "Why it matched:" |
| 6 | Footer | `flex items-center justify-between gap-2 pt-4 border-t` (hairline). Left (12px slate): `via {Source} · posted {Xd} ago · checked {Yh} ago`. Right: `button-secondary` (`h-10`) rendered as `<a href={url} target="_blank" rel="noopener noreferrer">`, label **View posting**, lucide `ExternalLink` icon, visually-hidden "(opens in a new tab)" |

### Salary tag
- Range: `₹12–18 LPA`. Single value: `₹15 LPA`. Up to 1 decimal place, trailing `.0` dropped (`₹4.5 LPA`). En dash between values. `tabular-nums`. Neutral style. Icon `IndianRupee` is not used (the ₹ sign is already in the text).
- Estimate (`salary_is_estimate`): `~ ₹12–18 LPA estimate`, outline style, with `Tooltip` text `Estimated by Adzuna. The employer did not state a salary.` The tooltip trigger is the tag itself, made focusable (`tabIndex=0`).
- Unknown: `Salary not stated`, outline style.

### Stale tag (D-03)
- Text `May be stale` with icon `TriangleAlert`, orange tag style (`badge-tag-orange`: peach `#ffe8d4` bg, `#793400` text).
- It is a `button` that opens a `Popover` listing the reasons (works on touch and keyboard; tooltips alone do not):
  - `stale_60d` → `First seen over 60 days ago and still listed.`
  - `reposted_3x` → `Reposted 3 or more times.`
  - `no_apply_url` → `No direct link to apply.`
  - Popover footer line (12px slate): `We show it anyway, ranked lower. Check the original posting before applying.`
- The tag's accessible name includes the reasons: `May be stale: reposted 3 or more times`.

### Freshness formatting (UI-04)
- `posted`: uses `posted_at`, falling back to `first_seen_at`. Under 24h → `posted today`. 1–59 days → `posted {n}d ago`. 60+ days → `posted {n}mo ago` (n = floor(days/30)).
- `checked`: uses `last_seen_at`. Under 60 min → `checked {m}m ago` (0 → `checked just now`). Under 48h → `checked {h}h ago`. Otherwise `checked {d}d ago`.
- Times are computed client-side from ISO timestamps. Wrap them in `<time dateTime>` with the absolute date in `title`.

### Source attribution
`via {source_display_name}` as returned by the API (e.g. `via Remotive`, `via Adzuna`, `via Greenhouse`). It is always shown and never truncated away.

## Filter Chips Contract (UI-05, D-05, D-09)

- One chip per hard filter present in `parsed.chips` / effective filters: **City**, **Min salary**, **Work mode**, **Seniority**. Skills and role words never become chips (D-05).
- Chip anatomy: DESIGN.md `pill-tab-active`. A `bg-foreground text-on-dark h-8 rounded-full` ink pill (white on ink 17.4:1) made of two buttons.
  - The **label button** (14/400, the value in 600, e.g. `City: **Bengaluru**`) opens the editor `Popover`.
  - The **remove button** (`X` icon, 16px glyph inside a 24px hit area, white) has `aria-label="Remove filter: City Bengaluru"`.
  - Focus ring on chips: 2px `ring-ring` with `ring-offset-2` (the offset keeps it visible next to the ink fill).
- **Add filter** button: DESIGN.md `pill-tab`. `h-8 rounded-full bg-transparent border border-hairline-strong text-muted-foreground hover:bg-surface`, with a `Plus` icon and the label `Add filter`. It opens a Popover menu of the filter types not set yet, and is hidden when all four are set.
- Chip labels:
  - City: `City: Bengaluru`. Multiple cities: `City: Bengaluru, Pune`. With remote_ok: `City: Bengaluru + remote`.
  - Min salary: `₹10 LPA+`. With estimates excluded: `₹10 LPA+ · no estimates`.
  - Work mode: `Remote`, `Remote or hybrid`, `On-site`, …
  - Seniority: `Senior`, `Junior or mid`, …
- Editors (inside the Popover: canvas, 1px hairline, 8px radius, `w-72`, `gap-4`). The footer has one button, `Apply filter` (`button-dark`, `h-10`). There is no cancel button. Esc or a click outside closes the popover without applying anything (Base UI Popover default), and focus returns to the chip:
  - **City**: `Combobox` (multi-select) over the city list, plus `Switch` "Also include remote jobs open to India". The city list should come from `GET /api/meta` (add a `cities: string[]` field, sourced from `cities.yaml`). Planner: add this to the API contract.
  - **Min salary**: `Select` with options `Any, ₹3, 4, 5, 6, 8, 10, 12, 15, 18, 20, 25, 30, 40, 50 LPA+` (the same buckets as the parse schema), plus `Switch` "Exclude estimated salaries" (D-09).
  - **Work mode**: `ToggleGroup` (multiple): `Remote`, `Hybrid`, `On-site`. Pressed items are ink with white text.
  - **Seniority**: `ToggleGroup` (multiple): `Intern`, `Junior`, `Mid`, `Senior`, `Lead`. Pressed items are ink with white text.
  - Switch "on" track: ink `#1a1a1a` (not brand).
- **Any chip edit, add or removal** writes the explicit filters to the URL with `auto=0` (`auto_filters=false`), so a removed chip never comes back (Pitfall 8). Then it re-runs the search.
- Model-sourced chips (`source: haiku | jev`) show a small `Sparkles` icon before the label and the visually-hidden text "suggested by {model}". Rule and user chips have no icon.
- `ParseSummary` (12px slate, above the chips): `Read by rules`, `Read by rules + Claude Haiku`, or `Read by rules + Jev`, from `parsed.parse_source`. When the search used no hard filters: `No filters found in your search. Add one below.`

### URL state (D-01)
Shareable, bookmarkable, and restored by back/forward. Param names must mirror the API query params in the generated client. Suggested: `q`, `city` (repeatable), `remote_ok`, `min_lpa`, `no_est`, `mode` (repeatable), `seniority` (repeatable), `auto`. The parse-model preference is **not** in the URL (it is a per-browser setting, see Settings). The page reads `useSearchParams` inside `<Suspense>` (Pitfall 11).

## Set-Aside and Relax Contract (UI-06, D-08, D-10)

- `SetAsideLine` (14px slate, one paragraph, items joined with ` · `), shown when any count > 0:
  `Of the 200 most relevant jobs, set aside: 34 below ₹10 LPA · 12 outside Bengaluru · 8 not senior · 18 US/EU-only remote`
  - Wording per filter: salary `{n} below ₹{x} LPA`; city `{n} outside {city list}`; work mode `{n} not {mode list}`; seniority `{n} not {seniority list}`; estimates `{n} with estimated salary`; geography (D-08, always present when > 0) `{n} US/EU-only remote`.
  - The "200" comes from the API's set-aside universe size (do not hard-code it if the API returns it).

    - `Include any city (+12 jobs)`
    - `Any seniority (+8 jobs)`
    - `Any work mode (+5 jobs)`
    - `Include estimated salaries (+6 jobs)`
  - Use `job` for a count of 1.
  - Clicking one applies that single relaxation (URL update, `auto=0`) and re-runs the search. Nothing is relaxed automatically (D-10).

## Settings Contract (D-06)

- Trigger: the header settings button. Opens a `Sheet` on the right (canvas, hairline left border), `w-full sm:max-w-sm`, with title `Search settings`.
- Field label: `Query parsing model`.
  - If `/api/meta.parse_models` contains more than one model: `RadioGroup`, with the selected indicator in brand:

    - `Jev` — description: `TypeSafe AI's decision model. Experimental.`
  - If it contains only `haiku`: static text `Claude Haiku` (no radio group). Never show a disabled Jev option.

- Changing it while a search is shown re-runs the current search. The sheet stays open, and the change is announced through the results live region.

## States and Interaction Contract

| State | Trigger | UI |
|-------|---------|----|
| Hero idle | No `q` in URL | Hero layout. Input autofocused only on desktop (`(pointer: fine)`), never on mobile |
| Submit empty | Search with blank or whitespace input | No request. `Field` error under the input: `Type a role, skill or city to search.` Focus stays in the input |
| First load | New `q` or filter change | Chips area keeps the previous chips (or nothing on first load). List shows 3 `Skeleton` cards (`h-44`, surface colour, 12px radius). `aria-busy="true"` on the list. Live region: `Searching…` |
| Results | 200 OK, ≥ 1 item | Cards. Live region: `{n} jobs found` (n = items loaded so far; there is no total) |
| Load more | `next_cursor` present | `button-secondary` `h-11` `Load more jobs`. While fetching: disabled, `Spinner` + `Loading more jobs…`. On success, 20 more cards append, focus stays on the button, and the live region says `20 more jobs loaded` |
| End of list | `next_cursor` null and ≥ 5 items | 14px slate centred line: `That's every match for this search.` |
| Few results | 1–4 items | Cards + RelaxSuggestions block |
| Empty | 0 items, relax suggestions available | `Empty` component (see Copywriting) + relax buttons |
| Empty, nothing to relax | 0 items, no relax counts > 0 | `Empty` with the "no matches anywhere" copy + 4 example-query buttons (`button-secondary`) |
| Degraded | `degraded: true` | `Alert` (canvas, 1px hairline, `Info` icon in slate, ink title, slate body) above the results. Results render normally |
| Rate limited | HTTP 429 (`error.code = rate_limited`) | `Alert` in orange tag colours (peach `#ffe8d4` bg, `#793400` title, body and icon) with the 429 copy. The previous results (if any) stay visible below it. The Search button stays enabled |
| Error | Network failure, 5xx, or Zod response-validation failure | `Alert variant="destructive"` on a **white** background: `#c92a2a` title and icon, ink body. It includes the error copy and a `Retry search` Button (`button-secondary`) that refetches. Previous results stay visible if present |
| Meta failed | `/api/meta` error | Hide the job-count line. The settings sheet shows Claude Haiku only |

Focus and keyboard:
- Enter submits the form. Esc closes popovers and the sheet; focus returns to the trigger (Base UI default).
- After a chip is removed, focus moves to the next chip, or to `Add filter` if none are left.
- After a relax button is clicked, focus moves to the `Top matches` heading (`tabIndex=-1`).
- Everything works with the keyboard alone, and focus is always visible:
  - On canvas: 2px slate ring, 6.8:1.
  - In the navy band: 2px white ring.
  - On inputs: 2px brand border.
- One `aria-live="polite"` region is used for all result announcements.
- Respect `prefers-reduced-motion`: no skeleton pulse, colour transitions or popover animation when it is set (`motion-safe:` prefixes).

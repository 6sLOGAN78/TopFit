Conventions:
- Commit messages end with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Capture uses the real adapters with live network ONLY in the operator command `ranker eval capture` run once by the executor during this plan; tests never touch the network (respx for the capture test).
- Stratified sample (≈100 total, in-scope and out-of-scope mixed): Greenhouse 20, Ashby 20, Internshala 20 (jobs and internships), Lever 10, Arbeitnow 10, RemoteOK 7, Remotive 6 (all in-scope it has), Jobicy 5; Adzuna 0 (no calls budget, ADR 0001). Include ≥ 10 postings the pipeline should skip (out of tech scope or on-site outside India) so scope accuracy is measured.
- Privacy: before writing the fixture, strip emails and phone numbers from captured text (regex) and truncate description_raw to 3,000 characters; postings are public job ads, stored only as eval data.
- Labelling protocol (honesty): gold labels are written by the executor from reading each posting's text, BEFORE running normalize_job on the set, and are never copied from normaliser output; each record has `labelled_by: "claude"` and `reviewed: false`. Plan 02-15 has the owner review ≥ 20 labels and set `reviewed: true`/fix them; the eval doc states both counts. Ambiguous cases get gold `unknown` with a `notes` string.
- Gold fields: in_scope (bool), remote_type (onsite/hybrid/remote/unknown), onsite_days_per_week (int or null), remote_eligibility, seniority, employment_type, salary_min_inr_annual / salary_max_inr_annual (int or null), city, country_code, industry. Scored only on in-scope gold postings except in_scope itself.
- Scoring: categorical fields → accuracy (exact), coverage (prediction ≠ unknown), precision on non-unknown predictions; salary → both-null agreement or within ±5% on both bounds; city → exact canonical; one shared report model printed as JSON and as a markdown table.
- Floors: floors.json = measured accuracy per field minus 0.05 (rounded down to 2 decimals), written once from the first scoring run; raising floors later is fine, lowering needs a note in the eval doc.

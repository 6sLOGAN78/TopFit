# 02-20: Workday adapter (public CXS JSON)

## Why
- Many large employers hiring in India use Workday. Examples: NVIDIA, Walmart Global Tech, Salesforce, Adobe, PayPal, Intel, Mastercard, Cisco, Target.
- Greenhouse, Lever and Ashby don't cover them.
- Owner decision 2026-11-28.

## Verified 2026-11-28 by the orchestrator
- `POST https://nvidia.wd5.myworkdayjobs.com/wday/cxs/nvidia/NVIDIAExternalCareerSite/jobs` with body `{"appliedFacets":{},"limit":20,"offset":0,"searchText":"India"}` returns `{total, jobPostings:[{title, externalPath, locationsText, postedOn, bulletFields}], facets:[...]}`.
- The tenant's robots.txt does not disallow `/wday/`. It allows the career-site path and disallows some sites and `/refreshFacet/`.
- **Re-check robots.txt for every tenant at startup or probe time. Skip any tenant that disallows `/wday/` or its site.**

## Scraping rules (owner relaxed D-15 on 2026-11-28; this replaces the D-15 text in this plan)
- Use an honest UA.
- robots.txt is advisory: log it, don't block on it.
- At least 1 s between requests to one host.
- Stop a scope on 403/429/challenge page. Never solve CAPTCHAs or Turnstile, never defeat anti-bot challenges, never spoof fingerprints, no rotating proxies, no logged-in scraping.
- SmartRecruiters (`https://api.smartrecruiters.com/v1/companies/{id}/postings`) is back in scope for 02-19.

## Tasks
1. **Location filtering.**
   - Prefer the tenant's location facet. The `facets` reply contains a `locations` or `locationCountry` facet; pick the India ids by descriptor match "India".
   - Fall back to `searchText: "India"` plus a location check on each row.
   - Paginate with `limit` 20 (Workday caps it there) up to `total`.
2. **Detail.**
   - `GET https://{tenant}.{wd}.myworkdayjobs.com/wday/cxs/{tenant}/{site}{externalPath}` returns `jobPostingInfo` with description HTML, location, `startDate`/`postedOn`, `timeType`, `jobReqId` and `externalUrl`.
   - Map to `RawJob`:
     - `source="workday"`, `source_scope=tenant`
     - `source_job_id` = jobReqId or externalPath
     - url = the public job page `https://{tenant}.{wd}.myworkdayjobs.com/{site}{externalPath}`
     - "Intern" in timeType or title maps to internship
   - Parse relative "Posted N Days Ago" only as a fallback.
3. **Config.**
   - `sources.yaml` gets `workday: tenants: [{tenant, wd, site, company}]`, a twice-daily schedule staggered after the other boards, and `max_details_per_tenant: 150`.
   - Probe about 40 well-known India-hiring Workday tenants. Find tenant/wd/site from their public careers links; the orchestrator-approved probe uses one CXS request per tenant, 1 s spacing.
   - Keep tenants with at least 5 India postings. Record probe results in `docs/decisions/0001-sources-spike.json` under a new top-level `workday` list.
4. **Expiry.** Use per-tenant scope absence expiry, consistent with how boardbase handles scopes and the 02-18 board-drop rules. A tenant whose listing fails expires nothing.
5. **Memory.** Process one tenant at a time and release its postings before the next (T-02-75 pattern).
6. **Tests.** Write respx fixtures covering:
   - the facet path
   - the searchText fallback
   - pagination
   - the detail mapping
   - the 403 stop
   - host validation rejecting bad config

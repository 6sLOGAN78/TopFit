<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tasks table → worker handlers | payloads are written by the API (later admin endpoint) and the pipeline; treated as data, dispatched only to registered kinds |
| worker ↔ Postgres | advisory locks and claims rely on DB connections |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Elevation of privilege | consumer dispatch | mitigate | dispatch only through the `build_handlers` mapping; unknown kinds go `dead` immediately, never imported dynamically |
| T-02-06 | Information disclosure | task logs / last_error | mitigate | log id, kind, error class only; payloads never logged; last_error stores `type(exc).__name__` |
| T-02-07 | Denial of service | poison task retry loop | mitigate | exponential backoff capped at 6 h, max_attempts → dead; deferral path for known transient conditions only |
| T-02-08 | Tampering | duplicate scheduler (double ingestion against quotas) | mitigate | session-level `pg_try_advisory_lock(727274)` on a held connection, re-verified every heartbeat; scheduler never imported in API |
| T-02-09 | Tampering | SQL construction | mitigate | bound parameters only; no f-string SQL (ruff S608 + grep acceptance check) |
</threat_model>

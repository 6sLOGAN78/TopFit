Conventions:
- Commit messages end with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The executor never handles or prints secrets. All SSH uses `ssh -o BatchMode=yes -i ~/.ssh/ranker_deploy deploy@<HOST>`; if it fails, stop and report (no other credentials). Server compose: `cd /srv/ranker && docker compose -f compose.prod.yaml ...`; CLI one-off commands (ingest/embed backfill) run in a SEPARATE short-lived container: `run --rm --no-deps worker python -m ranker.cli ...` — never `exec -T worker ...`, because exec would load a second fastembed model inside the running worker's 1g memory limit and risk an OOM kill of the scheduler/consumer. The one-off container gets its own memory limit from the same service definition and is removed afterwards.
- Production host: GCP e2-medium (4 GB) asia-south1, DuckDNS hostname; repo 6sLOGAN78/TopFit; GHCR owner 6slogan78.
- SQL used for the verdict (run with `exec -T db psql -U ranker -d ranker -At -c`):
  - active canonical embedded: `SELECT count(*) FROM jobs WHERE status='active' AND canonical_job_id IS NULL AND embedding IS NOT NULL AND embedding_model='BAAI/bge-small-en-v1.5'`
  - per source: the same grouped by source
  - runs: `SELECT source, mode, status, started_at, fetched, inserted, updated, unchanged, expired, failed, skipped, calls_used FROM ingest_runs ORDER BY started_at DESC LIMIT 30`
  - Adzuna calls per UTC day: `SELECT date_trunc('day', started_at), sum(calls_used) FROM ingest_runs WHERE source='adzuna' GROUP BY 1 ORDER BY 1`
  - enrichment: `SELECT kind, status, count(*) FROM tasks GROUP BY 1,2` and `SELECT count(*), sum(cost_usd) FROM llm_calls WHERE created_at >= date_trunc('month', now())`

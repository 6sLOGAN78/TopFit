## Phase Goal

**As a** TopFit operator, **I want to** have a fresh, normalised, embedded index of real India/remote tech jobs that one worker refreshes on a schedule without ever wiping it, **so that** search and ranking in later phases work on real, current jobs even when the LLM is unavailable.

<objective>
Gap closure for Phase 2, plus two Phase 1 review findings that matter before real traffic. Owner said "fix the gaps".

1. **Board-drop expiry hole** (02-14-SUMMARY "Known limitations"). A dropped board is no longer a complete scope, so its stored jobs never absence-expire. Fix: expire on drop, plus an age fallback that only fires for boards that answered recently. The volume-guard rule still holds: an outage must not empty the index.
2. **Greenhouse ingest memory** (docs/decisions/0001-sources.md "Production measurement", commit 6740c86). The one-off Greenhouse container sat at 1023 of 1024 MiB for about 5 minutes. Host swap reached 513 MB, and 32-row embed batches slowed from 6-8 s to 22-30 s. The scheduled run happens in the long-running worker, which has the same 1 GiB limit, so it risks an OOM kill. Fix it in code, not by raising the limit: process boards one at a time (fetch → normalise → upsert → release) and keep embedding in bounded batches.
3. **CR-01 + WR-04** (01-REVIEW.md). `/api/readyz` runs model inference on every public call. Change it to a startup self-check with a cached result. Also make SQLAlchemy hide bound parameters outside development.
4. **Lever/Ashby company names come from the slug** (02-14-SUMMARY). Add a configurable display name per board.
5. **Jobicy `geo=india` returned HTTP 400** (ADR 0001). Restrict `geo` to documented slugs, keep the feed unfiltered, and document why.
6. **FX rates are rounded and unconfirmed** (02-05-SUMMARY deviation). Refresh them once from the ECB reference rates. Rates stay static (D-12).

Purpose: keep the scheduled worker alive, stop stale board jobs piling up, close a cheap DoS path and a PII-in-logs path, and make job cards and salaries correct.

## Phase Goal

**As a** TopFit operator, **I want to** have a fresh, normalised, embedded index of real India/remote tech jobs that one worker refreshes on a schedule without ever wiping it, **so that** search and ranking in later phases work on real, current jobs even when the LLM is unavailable.

<objective>
Slice: "closed jobs leave the index, duplicates and ghosts are marked, but an outage never empties it". Per-source expiry (absence for full feeds, TTL for Adzuna and capped feeds) with the 50% volume guard (ING-08), simple cross-source duplicate grouping (D-18; full fuzzy ING-10 is Phase 6), repost detection and ghost signals (D-18), the D-20 per-run quality counters for those steps, and the source purge command needed by Adzuna's termination clause and the D-15 scraper rules.

Output: `ingest/expiry.py`, `ingest/dedupe.py`, `ingest/ghost.py`, pipeline hooks, `ranker purge-source` and `ranker expire-ttl` commands, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source availability → index state | a failing or degraded source must not destroy stored data |
| operator CLI → destructive purge | trusted operator, irreversible content removal |
| one source's rows → another source's canonical status | cross-source grouping lets one source's data hide another's |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-41 | Denial of service | index wipe after outage/partial fetch | mitigate | 50% median guard, cold-start rule, no expiry on partial/failed runs, per-scope absence, unseen-days only when source healthy, expired_by_run_id + reactivate_run for recovery |
| T-02-42 | Tampering | accidental purge | mitigate | `--yes` required, source name validated against the registry, prints affected count |
| T-02-43 | Repudiation / legal | ToS data removal | mitigate | purge clears all source-derived content fields while keeping row ids for referential integrity; dedupe recomputed so remaining sources stay visible |
| T-02-60 | Tampering | over-merging distinct jobs across sources | mitigate | dedupe_key keeps seniority and city/remote; grouping only hides non-canonical rows (never deletes); group_sources keeps every source visible; fuzzy merging deferred to ING-10 |
| T-02-61 | Denial of service | ghost rules hiding real jobs | accept | ghost_reasons are signals only (no status change); Phase 4 decides how to use them with a visible reason |
</threat_model>

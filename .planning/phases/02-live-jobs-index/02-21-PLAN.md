# 02-21: scraped sources with Scrapling (owner decision 2026-11-28)

## Why
- The owner relaxed D-15 for this non-commercial portfolio project and asked for Scrapling.
- Elip reportedly reads LinkedIn, Indeed, Naukri and Greenhouse.
- ADR `docs/decisions/0007-scraping-policy.md` records the new policy: what is allowed and the hard line on anti-bot evasion.

## Tasks
1. **Dependency and policy.**
   - Add `scrapling` (current stable, pinned) with `uv add`. Prefer the plain HTTP `Fetcher`, which needs no browser.
   - Only use `DynamicFetcher` if a source needs JS. If you do, document the Playwright browser install for the worker Docker image, but don't change the Dockerfile unless it is needed.
   - Write ADR 0007.
2. **`ranker/ingest/scrape.py`.**
   - Per-host async rate limit, at least 1 s.
   - Honest UA from `ranker.ingest.http`.
   - Timeouts.
   - `is_challenge(status, html)`: 403/429/503 with challenge markers, "captcha", "cf-chl", "Just a moment", "akamai", "px-captcha" and similar. On a challenge, raise `SourceBlocked`, so the run stops that source cleanly and expires nothing.
   - Selector helpers on Scrapling's `Adaptor`.
3. **LinkedIn source.**
   - Use the guest listing endpoint `https://www.linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search?keywords={q}&location=India&f_TPR=r86400&start={n}`. It returns HTML cards with title, company, location, date and job URL.
   - Queries come from config, for example "software engineer", "backend", "frontend", "data scientist", "machine learning", "intern" (internships via `f_E=1`), "devops".
   - Pages step by 10/25 up to a cap (default 300 cards per query).
   - Optional detail fetch from `https://www.linkedin.com/jobs-guest/jobs/api/jobPosting/{id}` for the description, capped (default 200 per run).
   - `source_job_id` = the LinkedIn job id. Dedupe against ATS copies happens downstream through the existing canonical dedupe.
   - Schedule twice daily.
4. **Naukri, Indeed and Internshala.**
   - Try one plain fetch each:
     - Naukri: its search JSON or HTML
     - Indeed: `in.indeed.com/jobs?q=...&l=India`
     - Internshala: the existing adapter, switched to the scrape helper
   - If a source gives real results, build the adapter the same way.
   - If it challenges, ship the adapter disabled (`enabled: false`) with the reason in a yaml comment and the SUMMARY. Don't try to get around it.
5. **Tests.** Use saved fixtures covering:
   - LinkedIn card parsing
   - detail parsing
   - pagination stop
   - challenge detection raising `SourceBlocked`
   - a blocked source expiring nothing
